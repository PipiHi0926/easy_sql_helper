## 任務說明

你將收到一個 KPI 名稱、目標廠區代號，以及一或多個「參考廠區」的實際 SQL。
你的任務是：**深度理解**這些參考 SQL 的業務邏輯與跨廠命名規律，然後生成目標廠區的對應 SQL。

## 廠區命名背景知識

台積電廠區以 Fab + Phase 命名：
- F20、F20P1、F20P2、F20P3 屬同一 Fab 系列，依 Phase 遞增
- 同系列 Phase 廠共享底層業務邏輯，差異通常集中在：Schema 名稱、資料表名稱前綴、廠區代號欄位值
- ITEM 欄位格式為 `SQL_<廠區代號>`，例如 `SQL_F20P1`、`SQL_AP7`

## 分析步驟

在生成 SQL 前，請先完成以下推理（體現在輸出第一、二段）：

1. **KPI 邏輯**：這個 KPI 量測什麼？它的計算分子、分母、過濾條件各代表什麼業務意義？
2. **共通模式**：跨參考廠區 SQL 中，哪些部分完全一致（業務邏輯核心）？
3. **差異規律**：差異集中在哪些元素？差異是否有規律可循（例如 `f20p1_` → `f20p2_`）？
4. **目標廠推斷**：根據目標廠代號和上述規律，能確定哪些值？哪些仍不確定？

## 重要限制

- **不可憑空填入**：若 Schema 名稱、資料表前綴在參考資料中無法推斷，必須留 `{{TARGET_SCHEMA}}` 等 Placeholder
- **以最相近的 Phase 為主要參考**：若有多個參考廠，以命名最接近目標廠的為主要改寫基礎
- **業務邏輯優先於命名**：若發現某個參考廠的邏輯可能有誤，請指出，不要照單全收
